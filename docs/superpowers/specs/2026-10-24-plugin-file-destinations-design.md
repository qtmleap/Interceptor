# Plugin file destinations

## Approved behavior

The user approved `Interceptor.createFile({ storage, atPath, contents })`, with folders and filenames selected by the Plugin's JavaScript, and requested an Enum for storage. Verify real Salmon Run JSON delivery into the physical M3's iCloud Drive/Salmon Run folder. Preserve unrelated primary-checkout work. No extra management screen, HTTP API, or manifest destination list.

```typescript
await Interceptor.createFile({
  storage: Interceptor.Storage.iCloudDrive,
  atPath: 'Salmon Run/history.json',
  contents: historyText,
});
```

`Interceptor.Storage` is an immutable runtime string Enum with `local = 'local'` and `iCloudDrive = 'icloud'`. SDK typing requires the Enum. `contents` accepts UTF-8 strings or exact `Uint8Array` bytes, including empty files. Promise<void> resolves on durable private publication; iCloud export/upload is later. Native storage does not parse JSON or require an extension. The Salmon Plugin validates each original response before submitting its unchanged text. Replace the unreleased saveJSON API throughout runtime, SDK, simulator and Plugin; no permanent alias.

## Paths, authority and persistence

`atPath` is relative to the virtual storage root; require NFC byte spelling and reject absolute/empty/dot/dotdot/hidden components, backslash, colon and control characters. Bound UTF-8 path to 1024 bytes, each component to 255 bytes, depth to 8. Derive a case-insensitive canonical identity; reject aliases rather than silently change user-visible spelling. Existing files belonging to another family or without native ownership cannot be overwritten. Same-family updates replace the original path. No read/delete API or permission attributes are exposed.

Keep schema-2 response.onLeave-only direct-call enforcement, write.files grant, current activation/package/capture-consent checks and cancellation fence. Keep 64 writes/16 MiB submitted contents per invocation, 1 MiB per file, 64 MiB/2048 files per family, 256 MiB/16 families aggregate, 1000 ms cumulative VM budget for files-granted runs, ordinary fetch 250 ms and wall 120 s. Empty files count toward file quotas. Rejected submitted callback attempts consume invocation budgets. C validates structure and bytes; Core validates NFC/case aliases. Reject non-NFC byte spellings rather than silently changing visible names. Retain the existing no-eviction capacity policy: capacity exhaustion rejects further writes; automatic data retention/deletion policy is outside this change.

New records live in App Group Library/Application Support/Interceptor/PluginFileRecords, separate from the existing JSON spool retained for previous results. Publish a single bounded versioned record containing validated routing header and original raw payload; length/digest validate on read. Exactly one stable destination-derived record name per family/storage/canonical path makes the latest commit win atomically. Cross-family aliases are checked under the root lock with bounded header-only enumeration. Descriptor-relative no-follow I/O, private protection and backup exclusion, bounded metadata and quotas, nonblocking interprocess publication lock, atomic rename/fsync. Prepare outside the activation fence and commit inside it. Do not split route and payload into independently committed files.

## iOS delivery

The extension only publishes private records. The main application uses its existing foreground loop to export raw payload bytes to Documents/Plugins/Files for local storage (separate from legacy namespaces), or into a user-authorized iCloud Drive folder for cloud storage. A system folder picker obtains a persistent minimalBookmark; start/stop security-scoped access and NSFileCoordinator coordinate provider writes. No hardcoded CloudDocs access path or new ubiquitous-container provisioning. The Enum object, its case properties and Interceptor.Storage binding are non-writable/non-configurable.

Use only necessary native permission UI. When cloud records are pending and no usable bookmark exists, the main app presents the system folder picker while active. Cancellation preserves pending records and suppresses repeat prompting until a later foreground entry. Existing approval footer explains iCloud sharing and foreground delivery. No new custom management screen. Grants are keyed by installation family and exact first path component, capped at 32 without eviction. For `Salmon Run/history.json`, the picker asks for the iCloud Drive `Salmon Run` folder, and the publisher strips exactly `Salmon Run/` before writing `history.json`. Validate the NFC prefix, exact case-sensitive UTF-8 boundary and nonempty remainder before I/O; validate the remaining path again. The original private record retains the full virtual path. Selected folder names must match exactly and report iCloud ubiquity, both on selection and bookmark resolution. Root-level files require a separate Drive-root grant; forbid overlapping root/prefix grants and case/compatibility prefix aliases within a family. Bookmarks survive normal updates and are requested again after access failure. M3 must visibly select/create the top-level iCloud Drive/Salmon Run folder; a matching folder name alone cannot establish that it is top-level.

Retain the original private payload on provider/offline/revocation failure and retry with bounded backoff. Native delivery state records what bytes were published, distinct from Apple's server upload status. A bounded private ownership ledger is keyed by persistent root identity and canonical path, recording family, published digest and an intent digest written before publication. Recover an interrupted publication only when the current file matches a recorded old/new owned digest; unknown or edited files conflict. Re-selecting the same physical root reuses its identity; another root does not inherit ownership. A serialized dedicated publisher queue uses cancellable NSFileCoordinator operations, holds scope until all owned I/O ends and compares the source again on subsequent passes. No hard OS I/O deadline is claimed. Use coordinated operations and no-follow destination traversal; do not apply app-private backup exclusion to exported iCloud documents. Native scratch filenames are journaled before creation and their inode before payload writes. Reclaim only the exact journaled, stale, unlocked regular single-link scratch: a matching recorded inode authorizes partial scratch cleanup, an absent inode requires empty contents, and a different inode requires the full pending digest. Published-file ownership/edit checks remain stricter. Never sweep unrelated external filenames. No source deletion or external-to-private import. Keep pre-existing user files and previous exported JSON. Present pending families in stable order, one picker at a time; cancellation suppresses further prompts for that foreground session. Refresh stale bookmarks while scoped when possible, otherwise re-prompt on a later active entry.

## Interfaces and ownership

- Core: `PluginFileDestination(storage: PluginFileStorage, atPath: String)` throwing initializer; immutable properties; `PluginFileStorage: String, Codable, Sendable` cases local/icloud (raw values above).
- Core: `PluginFileStore(directoryURL:)`, `prepare(revisionID:package:destination:contents:) -> PreparedWrite`, `PreparedWrite.commit(checkAuthorization:)`, `recordIdentifiers() -> [String]`, `readRecord(_:) -> PluginFileRecord`. Record exposes identifier, family, destination, contents, digest. Bounded header enumeration avoids loading every payload at once.
- Runtime: `JavaScriptFetchExecutor.CreateFile = @Sendable (PluginFileDestination, Data) async throws -> Void`; `runV2(..., createFile: CreateFile? = nil, transport:)`.
- C: `QJSCreateFileCallback(opaque, storage, storage_len, path, path_len, contents, contents_len, timeout_ms)` and `qjs_run_v2_fetch_files`, replacing unpublished fetch_save ABI. Borrowed length-delimited bytes; no binary string conversion.
- Native publisher/bookmark orchestration owned by Codex. Core records owned by Claude worker 1. C/Swift runtime plus SDK/simulator/hook owned by Claude worker 2. No worker commits or builds shared caches. Codex runs native tests, integrates processor, commits and verifies actual M3.
