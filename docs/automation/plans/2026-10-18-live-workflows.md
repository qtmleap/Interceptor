1. **Freeze Core contracts and regressions before integration.** Implement strict manifest v2 and separate workflow planning/result stage APIs/validators, retaining v1 JavaScriptHook/ScriptRunning/C validator and limits unchanged. Define ordered header/query/body projection DTOs; complete-HTTP versus transport-failure outcome; the shared canonical path helper; frozen plan codec/digest; immutable activation/delivery records; per-operation cancellation tokens; and all CAS states in the contract. Add failing boundary tests for 32 KiB raw/base64 bodies within the separate 96 KiB planning-result/192 KiB stage-input envelopes, invalid/extra fields, pointer absent versus null, duplicated query/header entries and unavailable/truncated bodies. Canonical path cases include encoded slash/backslash/dot/double escapes, uppercase escapes, trailing slash and segment-boundary prefixes. Every final method/path must satisfy both manifest and grant.

2. **Add the neutral capture seam in isolated Mudmouth.** Define immutable Sendable lifecycle snapshot and synchronous nonblocking try-offer sink, default nil, without any Automation dependency. Test CONNECT/inner-Host authority, duplicates/conflicts, exact header-pair preservation, request phases before any response, truncated data and nil/rejected-sink transfer compatibility. PacketTunnel owns AutomationCaptureAdapter and imports both libraries; the standalone Automation package never imports Mudmouth. Keep JS, storage/network waits and unbounded Tasks off the forwarding event loop.

3. **Implement shared activation and frozen planning transactions.** Stage/verify/encrypt exact immutable package bytes and commit the shared activation plus grant/settings/endpoint epochs atomically. Prove import remains inactive and the extension needs no app-private catalog/file access. IPC carries versioned IDs/expected plan digest/epochs only. For both modes, persist planning before evaluating one planner, then durably persist the validated exact request intent/wire representation, continuation, request projection/native header snapshot, identities/epochs, expiry and digest. Notify only after pendingReview commits. Manual Run CASes that displayed plan once to approved without JS replanning; Automatic uses the same pipeline. Tests mutate settings/source/grants between notification and Run, repeat taps/IPC, expire/revoke work and inject failures at each persistence boundary.

4. **Implement the extension-owned execution service.** Add bounded admission, native same-origin broker, deterministic ordered header filtering/regeneration, complete-response projection and one fixed result-stage invocation. Test no/replaced-body header stripping, Connection-nominated fields, proxy/framing exclusions, duplicate singleton conflicts, independent native forwarding versus JS reads, same-origin/path/grant checks and redirect refusal. Fully received 401/500 responses reach result processing; transport/timeout/partial/oversize failures never invoke result JS. No general fetch or Promise bridge is added.

5. **Implement durable transitions, delivery and recovery.** Enforce planning/pendingReview/approved/apiInFlight/resultReady/deliveryQueued/terminal CAS transitions and one operation/owner/session identity. Persist the API marker before network I/O; unknown API outcomes never replay. Claim the result invocation once before evaluating JS; recovery of an interrupted claimed invocation quarantines it. Atomically queue one immutable payload serialization, endpoint/credential revision and delivery UUID; put that UUID in Idempotency-Key and reuse it with identical bytes for all webhook retries. Test crashes before/after every marker/commit, concurrent worker claims, revocation between stages, exact retry bytes/key, lease expiry, rate buckets, disk/queue saturation and unrelated cancellation isolation. Fake transports use owned synthetic fixtures, not real user data.

6. **Adopt UI mocks, then integrate native routes.** Define a mock specification/component catalog for Off/Notify and Run/Automatic configuration, endpoint/grant review, frozen pending-plan review, status/history and error/empty/expired/unknown states. Obtain a human choice in Mock Diff Viewer before native UI work. Preserve token notifications and native toolbar behavior. Notification tap opens review without approval or I/O; denied notification permission leaves in-app pending access; stopped tunnels show restart guidance. Compare adopted native iPhone/iPad en/ja light/dark captures and clean only owned devices/resources. Standard text size follows the user's scope.

7. **Add compatible TypeScript templates/utilities.** Keep Bun, deterministic readable emitted JavaScript and initial self-contained helpers. Match the separate v2 stage/intent/projection contract, exercise emitted source with real QuickJS fixtures and verify max-sized valid envelopes. No ambient declaration is represented as a runtime helper implementation. Retain v1 examples, and publish live templates only after the compatible native runtime and publisher/verifier pins exist.

8. **Verify the integrated feature and release gates.** Obtain independent actual-diff reviews, required CI and app/extension builds. On actual devices verify shared encrypted package/key access, locked startup, request-before-response behavior, manual frozen-plan consumption, app-closed Automatic execution, direct egress/self-trigger exclusion (including DNS aliases), cancellation/revocation, pending notification routing and sustained tunnel overhead. Revalidate dependency pins and epochs against integrated content. Update applicable release/privacy evidence and distribute the authorized complete beta only after those gates. Use guarded Git for all new commits/pushes; do not modify user checkouts.
