## Cleanup and limitations

Every simulator run records studio, exact device set, pre-existing booted devices, Simulator windows/processes, and owned UDID before boot. Finally waits/stops its own test process, removes only its own fixture keys/server, shuts down/deletes the owned disposable device and verifies windows. Completed runs (including failed diagnostic runs) reported deletion and no cleanup errors. Active/future runs must be checked separately before claiming cleanup.

The VM allocator cap is 8 MiB, not process RSS. The 50 ms setting is a cooperative budget, not process isolation or a hard wall-time guarantee for every native engine primitive. Cleanup is not forcibly interruptible; Mac/simulator latency evidence does not establish physical-device limits. Physical VPN/Keychain/runtime acceptance and Apple review of downloaded-script behavior have not been performed. No foundation build was submitted or distributed.

The durable catalog uses protected staging and atomic rename; it does not promise F_FULLFSYNC/parent-directory crash durability. Sixteen remembered repository identities include removal tombstones, preserving trust/high-water state and consuming the lifetime cap. Crash-orphan staging files are not automatically swept. Corrupt data is preserved and surfaced, not silently reset.

Existing Ruby release-contract tests could not pass locally: system Ruby 2.6 lacks required syntax; Homebrew Ruby 4 ran them but the installed Git identity guard rejected test-fixture commits using synthetic identities (37 failures). No guard was disabled and no history was rewritten to bypass this. These release-tool fixture tests are separate from the passing Swift package/app evidence.
