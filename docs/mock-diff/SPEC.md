Planned screens: execution configuration; a pending-run review; pending/history lists; conditional permission review; Dangerous confirmation. The current example exposes only original-request Authorization and Cookie, no API response headers. Native same-origin inheritance is independent. Direct forwarding is only for immutable declared names to one confirmed endpoint, bound to exact revision/epochs; never infer consent from repository contents or script output. Cancel leaves the option OFF. Updates or destination changes invalidate old grants. Show names/destination, never secret values; use the native confirmation presentation in implementation. Modes are Off, Notify and Confirm (通知して確認), and Automatic. External sending is optional plugin behavior; show a destination only for a plugin declaring it, in the relevant configuration/permission flow. Do not force an endpoint on a local-only plugin. Run in the pending-review toolbar authorizes the displayed plugin execution. Notification tap only navigates. Show actual declared same-origin access and, when used, external-delivery scope; mask credentials. Denied notifications keep the pending list accessible. Loading/empty/revoked/expired/authentication/unknown-outcome states use the shared catalog and precise explanations.

Human selection in Mock Diff Viewer is required for new catalogs/screens. Do not write adoptions to imply approval.
